How a review runs

Rules give coverage and precision; the language model adds judgement. Every claim it makes has to point at a real line of code.

  1. Collect

    Load a folder, ZIP or GitHub URL. Code is treated as data and never executed.

  2. Detect

    38 generic rules flag secrets, injection, XSS, broken access control and database policy gaps.

  3. Mask

    Credential-like values are redacted before any code is sent to an AI provider.

  4. Review

    The model triages every candidate, rejects false positives and finds logic flaws rules miss.

  5. Ground

    Findings whose evidence line cannot be found in the file are dropped.

  6. Report

    Merged findings, attack chains and a prioritised plan in HTML, Markdown, JSON and SARIF.

Understands database access control

Reads every migration together: tables, foreign keys, RLS policies and grants, to catch privilege escalation and cross-tenant reads that single-file scanners miss.

Honest about uncertainty

Each finding is marked Confirmed or Needs validation with the assumption spelled out. Placeholder secrets are not reported as leaked credentials.

Fixes, not just alerts

Every finding ships a secure code snippet written for the same file, framework and table names, ready to paste and test.

Run it on your code

Python 3.9 or newer, no packages to install. Bring a Gemini, Claude, OpenAI or Groq key, or run a local model with Ollama.

git clone https://github.com/Santosh-2195/codewarden-ai.git
cd codewarden-ai
copy .env.example .env        (then add one API key)
python -m codewarden serve    (web interface)
python -m codewarden scan path\to\project --project "My App"
